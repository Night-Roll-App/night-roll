# Plan: Quiz — isolated (Josh: "build some quiz stuff too. Just keep it isolated")

Status: draft → **Fable-reviewed 2026-10-04 (this version)** → Fable build.

## Goal
A standalone quiz page (not linked from the app) for retrieval practice +
ear/sight drills, so session-start quizzes (memory: session-start-theory-quiz;
protocol: quizzes.md → docs/learning/quizzes.md after the tidy) can run in a
browser/iPad instead of only in chat.

## Isolation — decided
- **Location: `quiz/` at the repo root, NOT `src/quiz/`.** Verified: tools/split/check.mjs rule 8 (tests/modules.test.mjs L225) forces every file under src/ into index.html's modulepreload list, sw.js `APP_MODULES` and src/devtools.js — and devtools.js IMPORTS every module at app boot. src/quiz would be loaded by the app on every launch: the opposite of isolated. Outside src/, check.mjs ignores it and a quiz test enforces the import whitelist instead.
- Files: `quiz/index.html`, `quiz/quiz.css`, `quiz/main.js` (wiring only), `quiz/bank.js` (quizzes.md parser), `quiz/srs.js` (Leitner), `quiz/drills.js` (generators + answer checking), `quiz/tone.js` (WebAudio preview), `quiz/ui.js` (the only file that touches `document`). `quiz/index.html` has its own `<!doctype html>`, charset, viewport, no manifest, no SW registration.
- Allowed imports from the app: `../src/theory/chords.js` (pure), `../src/theory/key.js` (pure functions; it imports S but reads it only inside fileKeyAt/checkMeterVsFile, which the quiz never calls), `../src/ui/piano.js` (DOM-free geometry), `../vendor/vexflow.js` (global `VF`, for staff drills). Nothing from src/audio (needs S + the engine), ui/, session/, ask/, model/, platform/. Audio preview = `quiz/tone.js`, a 30-line WebAudio oscillator with an envelope — decided (the app's voices import the engine, transport and S).
- Theme: `quiz/quiz.css` copies the `:root` tokens from css/app.css (does NOT link app.css — 65 KB of app layout rules that would fight the page). A test compares `--bg --panel --panel2 --text --dim --accent --gold` values between the two files so drift fails the suite.
- Bank: `fetch("../docs/learning/quizzes.md")`, falling back to `../quizzes.md` on 404 (independent of the tidy's timing). The file is never written by the page. Status marks `[ ]/[x]/[~]` are parsed and shown, never changed.
- Device-local keys: `ff1roll-quiz-srs` (one JSON blob: per-question box + due) and `ff1roll-quiz-prefs`. Verified: `askEvictOthers` only touches `ff1roll-ask-*` and `hasExistingNightRollPrefs` only checks lastsong/cfg/ghtoken/notes-/draft-, so the quiz keys cannot be evicted by or flip anything in the app. Every read/write in try/catch; the page works with storage blocked.
- Not in the app's menus; not precached; not in the iPad package (tools/package.mjs `TOP_DIRS = ["vendor","icons","src"]` — quiz/ is never copied). Served by Pages at /night-roll/quiz/ (online only).
- Integration points (documented in docs/quiz.md, NOT wired): View ▾ → Tools → "Quiz" (opens quiz/ in a new tab), a help-sheet entry under data-hsec="explore", an AI "quiz me" hook (the general chat's system prompt could read the bank).

## The SW hazard (must ship WITH the page) — U3
Verified sw.js L147–161: every in-scope `navigate` request that is not
`sw.js`/`404.html` goes through `networkFirst(req, {key: "index.html", …})`,
and L121 does `c.put("index.html", r.clone())` — a visit to quiz/ would
OVERWRITE the cached app shell with the quiz page, and the app would open the
quiz offline. (privacy.html has the same latent bug.) Fix: at L146 return early
for `rel === "privacy.html" || rel.startsWith("quiz/")`; bump `SW_VERSION`;
tests/pwa.test.mjs case: the fetch handler source contains the bypass for
`quiz/` and `privacy.html` (source-text test, like the existing ones).

## Content
1. Bank mode: one question at a time; sections = `##`/`###` headings; questions = list items (52 today). Self-grade (got it / shaky / missed). Leitner 5 boxes, due = box interval; "shaky" = `[~]` semantics (box 1). Never invents answers (the file has none on purpose).
2. Drills (generated, general theory, never about Josh's songs): interval by sight (staff via VF; keyboard via piano.js geometry) and by ear (tone.js); chord quality by ear (maj/min/dim/aug/dom7/maj7/min7); scale-degree check (hear tonic + a degree, name the degree); key-signature recall (sharps/flats count ↔ key, both directions, via keyNameToSf/trueSf); note spelling in a key (spellPc/keySpelling). Difficulty steps (interval set grows; qualities added); streaks.
3. Learning-mode respect: drills are generic exercises; the page never opens a song, never reads `ff1roll-notes-*`/`ff1roll-draft-*`, never fetches albums/. Test: quiz/*.js source contains none of `ff1roll-notes`, `ff1roll-draft`, `albums/`, `S.song`.

## UI
Touch-first big buttons (≥44 px), dark tokens, iPad + phone widths (16 px gutter, no horizontal scroll), no native dialogs (`alert|confirm|prompt(` absent — test), audio starts only from a tap (iOS).

## Risks
- SW cache poisoning (U3) — the page must not merge without it.
- quizzes.md path moves in the tidy — the fallback fetch covers both orders.
- VexFlow global: vendor/vexflow.js is a classic script; the staff drill must tolerate `VF` missing (skip the drill, say why) — no page-level failure.
- iOS audio: WebAudio context resumed inside the tap handler, or the ear drills are silent.

## Out of scope
Linking into the app; AI-graded answers; syncing progress across devices; offline/precache; the iPad package.
